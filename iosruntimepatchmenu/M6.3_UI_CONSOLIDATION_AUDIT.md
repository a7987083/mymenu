# M6.3 Runtime UI Consolidation Audit

Baseline: `c071128e04cb2996cdf02de7ee29d07f7ab1e67e`

## Constraints

- Preserve Static/Offset and Runtime/IL2CPP backend behavior.
- Do not remove a UI/swizzle layer until its unique behavior is identified and migrated.
- Consolidate render-time post-processing incrementally and keep compatibility installer symbols.

## Confirmed UI responsibilities

- V053 Current UI: current page routing, diagnostics/debug routing, touch policy, current menu sizing and common controls.
- ZNFeatureGroupUI: public Feature grouping and themed feature toggle surface.
- ZNFeatureRuntimeControlsV2: converts base feature toggles to Button/Number/Slider controls and dispatches typed events.
- M5.8.5 Static Runtime Range: authored Slider range semantics (min=0, max=embedded sliderMax, step=1).
- M5.9.0 Unified Action Model: Builder semantics plus one-time persisted Number/Slider restore into runtime controls.
- M5.8.4 Scheme A: in-place layoutPanel/layoutSidebar/runtime-layout implementation.
- M6.0 Unified Feature Surface: safe Offset Hook ABI plus Static/Runtime vertical layout post-processing.

## Phase 1 consolidation

Migrate M5.8.5 Slider runtime semantics and M5.9.0 typed-value runtime restore directly into
`ZNFeatureRuntimeControlsV2`.

Compatibility installers remain callable, but M5.8.5 and the M5.9.0 runtime decorator no longer
add extra swizzle layers. M5.9.0 Builder validation/authoring behavior remains installed.

No backend execution path is changed in Phase 1.
